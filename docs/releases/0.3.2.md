# rmdex 0.3.2

专门修复 Android 切到其他应用后，任务完成通知要等返回会话才出现的问题。请配套升级 rmdex-pc 和 Android；仅更换 APK 不能修复旧 PC 的完成状态缓存。

## 修复

- PC 的任务状态接口直接核对最新任务记录，恢复漏掉完成事件后的状态，清理过期的运行状态和审批；并发读取合并，短时缓存避免重复读取。
- 完成事件在缺少启动事件时也会记录；旧任务的迟到完成事件不会清除新任务状态。流式回答保留比历史快照更新的文本。
- Relay 在旧 PC 状态缓存滞留时读取真实任务记录兜底；按具体任务判断完成，后续任务正在运行也不会阻止前一任务通知。监听覆盖排队接口直接启动并返回 turn ID 的任务。
- Android 通知凭证核对所属设备，切换设备后重新绑定；旧请求响应不会清除新凭证、覆盖新游标或发送旧设备通知。
- Android 在系统接受通知后才保存游标，失败时重试；退出时停止现有服务、断开请求，补充振动权限与诊断状态，避免前端与原生服务重复提醒。
- 推送继续使用原生后台服务直连 Relay；未接入 FCM，也不要求 Google Play 服务。

## 验证

- 50 项单元/状态回归测试、Relay 回归、多用户/员工迁移/员工通信、shared connection 和 MCP 集成测试通过。
- Web、Relay、PC 前端、Windows MSI、Android Debug APK 构建通过。
- Android 15 MuMu 独立包 `xyz.kyeai.rmdex.notificationtest`：真实 Relay 配合持续返回旧运行状态的模拟 PC，在系统设置前台和熄屏两种场景下，通知均在返回 rmdex 前出现；实测约 3–4 秒。已观察到系统横幅并核对高重要性通知渠道。
- 未用真实用户会话或生产数据测试。未覆盖各厂商实体手机、省电策略、强制停止、系统回收后恢复和通知点击返回会话；保留 `dataSync` 服务及其系统时限，不能承诺无限后台或被清理后离线送达。

可复现的模拟器检查见 `scripts/test-android-notifications.mjs`，测试专用构建与正式发布 APK 分离。

## 部署和回退

本次 GitHub 发布不自动替换生产 Relay 或本机已安装客户端。完整效果需配套安装新版 PC 和 Android；Relay 的旧 PC 兼容兜底及设备身份状态接口需要单独更新生产服务。

保留 v0.3.1 标签和安装包。回退 PC 前备份本地 work 与凭据；不要通过卸载清数据或强制降级处理版本问题。Relay 更新应保留当前持久化数据并保留旧容器，代码回滚不恢复旧 state。
